## Клиентский вход из канала в поиск

Канал остается лентой объявлений. Полноценный интерактивный фильтр внутри самой ленты сделать нельзя, поэтому точка входа в поиск остается через текущий сценарий бота в личке.

### Принятое решение

- Mini App исключен из плана.
- Развиваем текущую реализацию поиска в одном боте.
- Точка входа: ссылка из канала на бота с параметром `start` (`filter`, `client`, `search`).
- Поиск остается на текущем стеке Python + SQLite.

## Новые идеи (приоритет на рост удобства)

### Качество публикаций

- Черновик карточки с автосохранением каждого шага.
- Шаблоны описаний по типам объектов (квартира/дом/офис/склад и т.д.).
- Проверка на дубликаты перед публикацией (адрес + цена + площадь + последние публикации сотрудника).

### Удаление и статусы

- Восстановление удаленной публикации из папки "Архив" (в течение ограниченного времени, например 24 часа).
- Отдельный сценарий "Исправление": создать новую карточку на основе удаленной (предзаполненная форма).
- Расширенные причины снятия (продано/ошибка/исправление/неактуально/дубликат) с аналитикой по причинам.

### Поиск и клиентский UX

- Избранное для клиента (сохранение объявлений в личке бота).
- Фильтр "только с фото/видео".
- Быстрые пресеты фильтров: "до N USD", "Ташкент", "Жилое", "за 7 дней".

### Контроль сотрудников

- Карточка сотрудника с таймлайном действий (публикации, удаления, правки, заявки).
- KPI-блок: публикаций за 7/30 дней, снятий по причинам, доля ошибок.
- Ограничения на публикации для новых сотрудников (например, лимит в день до одобрения админом).

### Аналитика и отчеты

- Автоотчет в ЛС владельцу/админу по расписанию (ежедневно/еженедельно).
- Воронка: создано -> опубликовано -> снято -> продано.
- ТОП районов/категорий по количеству публикаций и снятий.

### Надежность и техдолг

- Таблица service_messages в БД для устойчивой очистки после перезапуска (без зависимости от FSM state).
- Централизация рендера логов и единый формат строк (чтобы не править 3 места вручную).
- Команда сервисной диагностики: проверить "осиротевшие" сообщения/записи и предложить очистку.

## Классные, но не экстренно-критичные

- Массовые действия: выбрать несколько публикаций и снять/архивировать одним действием.
- Отложенная публикация: создать карточку сейчас, опубликовать по расписанию.
- Напоминания по "старым" активам: если объявление висит 30+ дней, пинг сотруднику "обновить/снять".
- Умное предупреждение перед публикацией: если цена/площадь сильно выбивается из типичных значений, просить подтверждение.
- QR/короткая ссылка на объявление для быстрого шаринга и оценки интереса.
- История правок карточки: кто/когда/что изменил.
- Антифлуд для сотрудников: лимит N публикаций в X минут + мягкие предупреждения.
- Дополнительные роли: "модератор" и "суперадмин" с разграничением доступов.
- Сегменты в логах: быстрые кнопки "только публикации / только удаления / только ошибки".
- Панель "проблемные публикации": без фото, с пустыми полями, подозрительные цены.
- Автовалидация контактов с подсказками исправления формата.
- "Копировать как новую": создание новой карточки на основе старой.
- Шаблон сотрудника при регистрации: обязательные поля + чек-лист перед выдачей доступа.
- Единый "центр уведомлений" для админа: заявки, ошибки, удаления, сбои экспорта.
- Мягкая очистка чата по режимам: разные профили для владельца/админа/сотрудника.
